# 业务规则到回调验证：流程差距与当前状态

## 原有流程的差距

原项目已经具备固定教学合约、手写回调合约、手写测试、静态共享状态分析和可视化报告，但研究者无法只通过业务规则驱动验证。缺少的关键环节是：

1. 没有稳定、可审查的业务规则输入格式；
2. 没有把规则转换成回调测试的生成器；
3. 没有在生成前拒绝公网、RPC、钱包、私钥、任意地址或任意代码等越界输入；
4. 没有把“预期保持/预期违反”与实际观察逐项对照的机器可读报告；
5. 没有一个命令串起规则校验、测试生成、本地执行和报告输出。

## 本轮补齐的闭环

```text
研究者按 rules/callback-rules.schema.json 编辑 rules/callback-rules.json
        ↓ 严格 schema、白名单模板、参数上限和本地边界校验
scripts/generate-callback-tests.mjs
        ↓ 只生成已审查模板对应的 Hardhat 测试
test/generated/callback-rules.test.ts
        ↓ Hardhat 临时内存链执行漏洞版/修复版
analysis/business-rule-report.json + .md
```

入口命令为 `pnpm verify:rules`。规则文件不接受可执行代码，不接受合约地址、RPC、网络、账户、钱包、助记词或私钥。生成器只能选择项目内三个已审查的回调适配器。

## 当前支持的研究规则模板

| 模板 | 业务不变量 | 可配置参数 |
|---|---|---|
| `one-time-mint` | 一次性资格最多得到一枚 NFT | 无 |
| `collateral-coverage` | 未偿债务不超过剩余抵押能力 | `borrowAmount`：11–20 |
| `funded-value` | 最终支出不超过调用者提供的价值 | 数量 1–10、单位存款 1–5、附加数量 1–3 |

## 仍然有意保留的限制

- 不根据任意 ABI 或自然语言自动合成 Solidity 回调合约；新增协议需由维护者实现并审查一个新的模板适配器。
- 不连接公开网络、测试网、钱包、价格源或真实资产。
- 当前采用少量确定性参数，不是无限制模糊测试或形式化证明。
- 静态候选路径仍是审查提示；业务规则执行结果只证明这些本地教学模型中的观察。

这些限制是本地教学工具的安全边界，不是待接入真实交易能力的缺口。
